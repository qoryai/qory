# qory 0.3.0

The first release shaped by an integration: a harness repository moved four modules and
two stacks off its own composer onto qory 0.2.x and wrote down what it had to work
around. This release takes every item of that report.

## Upgrading from 0.2

- A stack or a `qory.yaml` with a `qory` key is refused by a 0.2.x binary as an unknown
  key, exit 2. Upgrade every machine before a delivered stack gains the key.
- A `qory-stack.yaml` at a repository root without an `extending` block is refused. Move
  its target and modules under `harness` in `qory.yaml`; `qory setup repo` writes one.
- `qory version` prints the number without a `v` from every kind of build. A script that
  read the `v` reads `qory version --json` instead.
- The instructions land at `.claude/CLAUDE.md` for Claude Code and at `AGENTS.md` in the
  home. A root `AGENTS.md` exists only for a runtime that reads one; add `any` to
  `target.runtime` to get the link at the root.

## A document states the qory it needs

`qory: ">=0.3.0"` on a `qory-stack.yaml`, or on a `qory.yaml`, holds comparators such as
`>=0.3.0 <0.4.0`. Compose and worktree add check every document they read before
anything is fetched or written and exit 5 outside the range, naming the file, the version
and the range. A delivered stack states its minimum once, and every repository extending
it inherits the range: upgrading qory on the runners changes no client file. A build from
source between tags has no version to compare, so it composes and prints one row saying
the range was not checked.

## `qory version --json`

```json
{"version": "0.3.0", "commit": "a1b2c3d4e5f6", "dirty": false, "source": "release",
 "harnessFormat": "qory.ai/v1alpha1", "reportVersion": 1}
```

`source` is `release` for a release build and `source` for a `go install` or `go build`,
which is how an installer leaves a developer's own build alone. The report records the
same three fields under `qory`, so a runner's report and a laptop's can be compared.

## `qory harness compose --check`

The merged outputs, the instruction file, the settings, the MCP file, are generated
copies, so an edit to a module's instruction section leaves the composed one stale until
the next compose. `--check` renders again into a scratch directory, compares it with the
home, and exits 6 naming each path that differs, or saying nothing is composed. It writes
nothing. A CI job runs it as a gate.

## Part of a module

`exclude` and `only` on a stack module read the same keys: the seven entry kinds with
names, `instructions: true`, and `settings` and `env` as `true` or a list. Under
`exclude` a named thing is left out. Under `only` a named thing is composed, together with
what it requires from the module, and nothing else:

```yaml
- name: ops
  only: {skills: [deploy]}          # deploy, the command it runs, the agent it calls
  exclude: {agents: [reviewer]}     # that agent comes from another module instead
```

What an entry requires is declared once, in the module's manifest:

```yaml
requires:
  - skill: deploy
    commands: [ship]
    agents: [reviewer]
```

A composed entry whose requirement is not composed is refused: `module ops: skill deploy
requires command ship, which module ops leaves out`, or `which no module ships`. Two
modules contributing one entry stays a collision, resolved by an explicit line as before.
The report lists every entry and part a block left out, and marks each pulled entry with
the entry that required it.

## Exit statuses

| Status | Meaning |
|---|---|
| 5 | the running qory is outside the range a document's `qory` key declares |
| 6 | `--check`: the home no longer matches what the stack and modules say |

## Also

- A root `qory-stack.yaml` with no `extending` block is refused with the place a
  repository's own stack goes. The same file through `-f`, in an ancestor directory, or
  through `extends` reads as before. The hello example is a `qory.yaml` now.
- The README describes the composed tree and the tools that have to follow its links:
  `find -L`, BSD versus GNU `grep -R`, `rg --follow`.
- A `+dirty` suffix on a version Go stamped into a source build was not recognised and
  printed as a version.
